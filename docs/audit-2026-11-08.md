# PilotPatch audit — 8 November 2026

Scope: repeat audit of `main` at `619de09`, followed by regression fixes in 0.2.1.
Reviewed the Edge extension, encrypted local protocol, browser reply parsing, agent
permissions/tools, terminal reporting, session retention, setup guide and package paths.
The user’s actual Edge profile, account and Copilot conversation were not inspected.

## Findings and fixes

| Priority | Finding | Trigger and consequence | Resolution |
| --- | --- | --- | --- |
| P1 | Pairing replacement retained old authority | Import a different pairing while connected: the worker retained its old token/client snapshot and could continue operating for the old connection. | Pairing changes revoke selection; the worker checks current pairing/client as well as tab selection before operations. |
| P1 | A delayed click outlived revocation | Change selection/disconnect during the 100 ms input delay: the old content script still clicked Send. Revocation while injection awaited could also fill the old composer. | Prepare without sending; recheck after injection and preparation; request a one-shot grant from the still-active CLI; recheck and synchronously commit in the pinned document. |
| P1 | Example JSON could become a tool action | A reply containing a warning plus one JSON code block lost all surrounding prose before strict parsing. | Preserve substantive prose; strip only empty wrappers or the JSON language label. Example/warning replies fail protocol validation. |
| P1 | Code-copy controls could mark a partial reply complete | A streaming code block exposed Copy before the response finished and its stop/busy indicator was absent or unrecognized. | Require message-level completion; reject generic Copy/code-copy controls, including with legacy broad selectors. |
| P1 | Completed-task rendering threw an exception | `ui.report` passed unsupported `markup=False` to Rich `Panel`, making a successful task end with a CLI error. | Render a `Text` object inside the panel. Approval prompts also use literal `Text` so command strings cannot hide text through Rich markup. |
| P2 | Retention skipped old or abandoned-lock sessions | Pruning used the 100-entry history view and treated any legacy lock marker as an active lease. Expired completed sessions could remain indefinitely. | Scan all validated session records under an external task lease; probe legacy leases instead of relying on file existence. Keep active and unfinished tasks. |

The submission fix also needed an upgrade boundary: an old installed extension must
not silently receive new prompts and bypass the commit step. Protocol 2 is required
before payload delivery, successful submission receipts require the grant, and the
versioned content channel keeps orphaned v1 listeners from acting on upgraded commands.
The backend reports that an old extension must be reloaded before any prompt is sent.

## Regression evidence

Before the fixes, local browser fixtures reproduced warning removal, accepting a
partial code block as complete, and Send occurring after tab/pairing revocation.
A real Rich render reproduced the completed-task `TypeError`. Filesystem fixtures
reproduced retention failure beyond the history window and with an abandoned marker.

Added coverage includes:

- Both managed and existing-Edge adapters retaining warning prose and waiting for
  message-level completion, including old operator completion selectors.
- Revocation on selection change, disconnect, pairing replacement and CLI shutdown
  during preparation; revocation while script injection is awaiting completion.
- A legacy worker receiving no prompt; a legacy content listener ignoring v2 commands;
  a live pending command receiving exactly one commit grant; rejection of ungranted
  successful submission receipts.
- Retention beyond 100 entries, abandoned legacy markers and active old/new leases.
- Literal approval text and a completed-task report that renders without an exception.

The existing encrypted transport, replay protection, source-sharing, filesystem,
permission and unknown-outcome tests remain part of the full suite. A fresh independent
source review found no remaining blockers in the revised submission path.

Final checks: **134 Python tests passed, 5 skipped** (four explicitly gated live-account
tests and one Windows symlink privilege test); **13 Node checks passed**. Ruff lint and
format checks, `pip check`, Python wheel/sdist and VSIX builds passed. The installed
wheel's seven extension assets match source, the existing-Edge default and external
task leases were checked, and all 40 setup PowerShell blocks parse. Python lockfile
and editor npm dependency audits reported no known vulnerabilities.

## Operational limits

Offline tests and local DOM fixtures cannot prove current signed-in Copilot selectors,
service availability, real multi-turn model behavior or account-specific authorization.
The default completion selector now requires **Copy message**; a live UI with a different
message control needs an operator-verified selector. Generic Copy is insufficient.

The Copilot host allowlist was checked against Microsoft's
[published terms](https://www.microsoft.com/en-us/microsoft-copilot/for-individuals/termsofuse),
which list `copilot.microsoft.com`, `copilot.com` and `copilot.ai`. This check establishes
documented destinations, not permission for automation. The personal service terms'
automated-access restriction remains documented in the README; applicable account and
organization agreements were not validated by this audit.

## Apply the update

1. Stop the old PilotPatch task yourself; keep your regular Edge window open.
2. Update the backend to 0.2.1 and run `copilot.cmd connect`.
3. On `edge://extensions`, **Reload** the PilotPatch extension in the same Edge profile.
4. Open its popup and select your existing Copilot tab again.
5. Run `login`, `status` and `probe` in order. Only a successful probe verifies a real reply.

See [setup.md](../setup.md) for the complete PowerShell commands. No alternative model,
profile import, hidden Microsoft endpoint or authentication bypass was introduced.
