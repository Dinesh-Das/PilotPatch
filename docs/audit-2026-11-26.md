# Office Windows setup audit

The audit covered the offline ZIP, PowerShell 5.1 installer, VS Code backend selection,
Edge pairing and the local connection test.

| Priority | Finding | Fix |
| --- | --- | --- |
| High | Missing bundle files could send setup down an online install or build path. | Mark the office ZIP and check for its wheelhouse, exact backend wheel and requested VSIX before creating the environment. |
| High | VS Code setup relied on `code.cmd` being on the shell's `PATH`. A failure also left the Edge setup files unprepared. | Search the standard user and system install locations. Prepare Edge and register the backend before attempting the editor install. [VS Code on Windows](https://code.visualstudio.com/docs/setup/windows#_common-questions) |
| High | A manually selected Python could silently take precedence over a newer setup. | Show the selected backend's source and let the user switch to the one registered by setup. |
| Medium | The installer could pick a Python interpreter that lacked compatible Windows x64 wheels. | Check the Python build's platform during launcher discovery and before installing. |
| Medium | An occupied or denied loopback port surfaced as an operating-system exception. | Identify the port and distinguish a conflict from a permission denial. |

The bundled wheel variants cover Windows x64 and Python 3.11–3.13. The local install
check uses PowerShell 5.1 and Python 3.12. A test on the managed device still determines
whether its policies allow the installed extensions, local loopback and the intended
Microsoft account. The connection test sends a short message without project files.
