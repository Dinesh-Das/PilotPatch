# PilotPatch follow-up audit

The review traced a task from the VS Code panel through the Python agent, Edge
bridge, repository tools, review approval and offline packaging. The table records
confirmed defects and the behavior in 0.5.1.

| Priority | Finding | Resolution |
| --- | --- | --- |
| High | A range that started inside a private key could return the key body. A Git patch could also contain an interior line from an old key without either delimiter. | Scan key markers before the requested range and redact both full Git diff inputs before generating the patch. Count range and diff limits in UTF-8 bytes. |
| High | An open loopback connection could hold an Edge task and its browser lock during shutdown. A waiting browser command was left to time out independently. | Abort tracked sockets before waiting for the listener to close, finish the waiting command, and release the lock. Browser actions retain the existing replay safeguards. |
| High | A failure after the first approved write hid recorded changes in VS Code. Skipping an interrupted review write on resume expected a Copilot fingerprint that local writes lack. | Surface confirmed writes and the file to check. Resume after an explicit skip without replaying the interrupted write. |
| Medium | A repository scan could omit a file restored by a nested ignore rule and parse a root ignore file repeatedly. | Apply the closest matching rule and cache ignore-file parsing for the duration of each scan. |
| Medium | A repository diff started one Git subprocess for every inspected file. | Query object metadata in one batch and load original content only for changed files. Use local Git objects and guarded file reads. |
| Medium | A resumed task could exceed its context budget by appending old receipts to a nearly full prompt. | Reserve context for continuation, retain the newest receipts that fit, and keep the instruction to verify current files. |

The Git implementation uses object metadata without running checkout filters.
[Git object inspection reference](https://git-scm.com/docs/git-cat-file).

## Windows benchmark

Median of four calls on a temporary repository with 120 tracked Python files
across 12 directories, one root ignore file and one modified source file.

| Operation | Before | After |
| --- | ---: | ---: |
| Repository inventory | 47.6 ms | 42.8 ms |
| Filtered Git diff against HEAD | 4,140.4 ms | 198.4 ms |
| Git subprocesses per diff | 121 | 2 |

## Verification scope

The audit uses local Git fixtures, offline browser and editor tests, and Windows
package validation. Live behavior with a signed-in Microsoft account and extension
installation policies on a managed office laptop require validation on that account
and device.
